# Supplementary Data and Code

This archive implements the Data and Code Availability statement in the manuscript **No Petals Plucked: In-Silico Bioprospecting for the Shirui Lily**.

## Contents

- `code/` - final executable Google Colab notebook used for the completed experiments.
- `study_artifacts/sirolily_geometric_bioprospecting/data/raw/` - immutable ChEMBL and PubChem source snapshots.
- `study_artifacts/.../data/processed/` and `strict_sensitivity/.../data/processed/` - broad and strict curated endpoint tables.
- `study_artifacts/.../logs/` - exclusion/filter/replicate audits and training/QC logs.
- `study_artifacts/.../data/splits/` and cross-validation `splits/` - scaffold-disjoint split manifests.
- `study_artifacts/.../strict_sensitivity/alox15_scaffold_cross_validation/tables/` - out-of-fold predictions and cross-validation statistics.
- `study_artifacts/.../tables/` - model metrics, predictions, bootstrap comparisons, ablations, uncertainty diagnostics, and candidate results.
- `paper_figures/` - the five exact figures used in the manuscript.
- `DATA_AND_CODE_AVAILABILITY_COVERAGE.csv` - maps every promised availability item to its location.
- `PUBLIC_DATABASE_SNAPSHOT_VERIFICATION.csv` - verifies raw snapshots against the original experiment manifest.
- `SHA256_MANIFEST.csv` - package-level cryptographic checksums.

## Reproduction

Open `code/Siroi_Lily_Geometric_Bioprospecting_A100_Final.ipynb` in Google Colab, select an NVIDIA A100 runtime where available, and run the notebook top-to-bottom. The notebook contains package setup, API acquisition, standardization, conformer generation, graph construction, baselines, neural training, strict sensitivity analysis, scaffold-disjoint cross-validation, candidate screening, figures, and export logic.

The large derived PyTorch graph cache (`graph_store_paper.pt`) is intentionally not duplicated here because it is not part of the manuscript's Data and Code Availability promise and is deterministically regenerated by the executable notebook from the included curated structures/conformer pipeline. Model checkpoint binaries are likewise not required by that paragraph; all reported predictions, metrics, splits, and figures are included.

## Integrity

Candidate provenance is preserved in `input/candidate_metabolites.csv`, `data/processed/candidate_metabolites_standardized.csv`, and the final candidate prediction table.
